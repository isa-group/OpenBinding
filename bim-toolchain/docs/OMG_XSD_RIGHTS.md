# OMG BPMN 2.0.2 XSDs: rights inventory

**State: NOT DEMONSTRATED (NO DEMOSTRADO).** Nothing in this repository shows that OMG allows the five XSD files to be
redistributed. The files are vendored for the private repository; they are **blocked in the export** until the holder
records a clearance in `licenses.json` (below).

## What the files are

`packages/bim-core/src/bim_core/resources/vendor/omg/bpmn/2.0.2/` holds `BPMN20.xsd`, `Semantic.xsd`, `BPMNDI.xsd`,
`DC.xsd` and `DI.xsd` plus a `README.md` that says they were "downloaded unchanged on 2026-08-09" from
<https://www.omg.org/spec/BPMN/20100501/> (index: <https://www.omg.org/spec/BPMN/2.0.2>). They are part of
`compilerDigest` (it covers every file under `resources/`), are read through `importlib.resources`, and are needed to
validate BPMN workflows without network access.

## Official findings of the controller (`outputs/OMG_XSD_FINDINGS_20261014.md`), as received

Summary, verbatim from the contract that ordered this work:

> La página oficial BPMN 2.0.2 lista los 5 XSD sin enunciar licencia de redistribución; muestra «IPR Mode: RF-RAND»;
> `BPMN20.xsd` y `Semantic.xsd` tal como los sirve omg.org no traen comentario de copyright; los términos del PDF de la
> especificación (copia/distribución) no han sido leídos por el controlador; el estado es **NO DEMOSTRADO**.

In English: the official BPMN 2.0.2 page lists the five XSDs without stating a redistribution license; it shows
"IPR Mode: RF-RAND"; `BPMN20.xsd` and `Semantic.xsd`, as omg.org serves them, carry no copyright comment; the terms of the
specification PDF (copying and distribution) have not been read by the controller; the state is NOT DEMONSTRATED.

What this does and does not allow one to conclude: "RF-RAND" names the intellectual-property mode under which the
specification was adopted (royalty-free, reasonable and non-discriminatory terms for patents). It is not a copyright
license for the files and it does not say that they may be redistributed. The absence of a copyright comment in a file is
not a grant either. This repository does not read either as clearance. The full findings document is not part of this
repository and was not available to this work: only the summary above was.

## Options

Each of the four is a legal decision of the holder; none is taken here.

1. **Written confirmation from OMG** that the files may be redistributed with this repository, and under which terms.
   Record it in `licenses.json` (`cleared`, `cleared_by`, `cleared_on`, `evidence`) and the export includes the files.
2. **Do not vendor; download from the official source and verify the SHA-256 at build time.** Implemented:
   `python tools/xsd_inventory.py --fetch packages/bim-core/src/bim_core/resources/vendor/omg/bpmn/2.0.2` downloads the
   five files over https from `source_base`, compares each with the SHA-256 declared in `licenses.json` and writes nothing
   unless all five match. With the same bytes in place the `compilerDigest` is the one of this repository (it covers the
   bytes, not the way they arrived). The exported workflows run that step first (see below).
3. **Own validation**: replace BPMN validation by a schema written for this repository. Not done: it would change
   `bim_core` and therefore `compilerDigest` and every golden.
4. **Keep the repository private and accept the risk**: the files stay in the private repository only. Nothing is
   exported while this is the option in force.

## The export switch

`licenses.json` → `omg_bpmn_xsd.cleared` is the versioned switch. It is `false` and `status` is `not-demonstrated`.

* `tools/export_repo.py` (default `--xsd auto`) leaves the five files out while `cleared` is not `true`. `--xsd exclude`
  leaves them out whatever `cleared` says. `--xsd include` is refused unless `cleared` is `true` and `cleared_by`,
  `cleared_on` and `evidence` are filled.
* An export without the files sets `present_in_tree` to `false` in its `licenses.json`, keeps the vendored README (the
  declared origin and SHA-256), and adds a step to its workflows, right after each checkout, that runs
  `tools/xsd_inventory.py --fetch`. Without the files the tests that compile BPMN cannot run: the export tool therefore
  runs its own self-containment test on a temporary copy in which the files are restored from the source tree after
  verifying their SHA-256 (the equivalent of the verified download, without network).
* To clear them: edit `licenses.json` as described in its `cleared_format`, run `python tools/xsd_inventory.py --check` and
  export again.

## What would be needed from the holder

A decision among the four options and, for option 1, the written confirmation or the terms read (and who read them).
Until then the state stays NOT DEMONSTRATED and the export blocks the files.
