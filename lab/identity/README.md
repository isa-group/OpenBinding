# The SCORETech Identity lab

OpenBinding signs in with SCORETech Identity when `AUTH_PROVIDER=scoretech` ([docs/IDENTITY.md](../../docs/IDENTITY.md)).
Locally, and in the final verification of every Identity pull request, the real Identity runs as its own lab, at a pinned
revision, beside OpenBinding's lab. CI never uses it: the gateway suite runs against an in-process fake issuer.

| Piece | What it does |
|---|---|
| `up.sh` | clones `SCORELabUS/SCORETech-identity` into `.lab/scoretech-identity` (gitignored), checks out and verifies `215dffedf556294e2424f7c7b4e9bf57d038d66f` (v0.1.11), refuses busy ports (18000, 18025, 18198) or too little memory for both stacks, and runs Identity's `./lab up` with `IDENTITY_ACCOUNT_RETURN_ORIGINS=http://localhost:18198`. `IDENTITY_PROVIDER_IMAGE` pre-pulls the published provider image (`ghcr.io/scorelabus/scoretech-identity-provider:sha-215dffe…`) to skip its Maven build; `IDENTITY_LAB_SOURCE` clones from a local copy instead of GitHub |
| `down.sh` | `docker compose -p scoretech-identity-lab down --volumes` (Identity's own `./lab down` keeps the volumes) |
| `fixtures.mjs` | run inside Identity's `account-api` container with Keycloak's admin API: a confidential client `ob-walk-<run>` exactly like a managed application (PKCE S256, the scope mapping of `openbinding:access`, the default scopes `profile` and `email` only, the four mappers of a managed application, the shared fields `email`, `name`, `display_name` and `avatar`, a 60-second access token) and the users `ob-walk-<run>-{admin,member,research,norole,clash,squat}`; `inspect`, `grant`, `claims` (names only) and `delete` |
| `walk.sh` | the whole walk below, with cleanup always |
| `../../compose.lab-identity.json` | the overlay: the gateway in `scoretech` mode on Identity's network (`SCORETECH_IDENTITY_TRANSPORT_URL=http://keycloak:8080/…`, the issuer stays `http://localhost:18000/…`), the client secret by file, and `e2e-identity`, Playwright with host networking |

```bash
WALK_LOGS=/tmp/identity-walk IDENTITY_SECRET_DIR=$HOME/.ob-identity-secret BIM_TOOLCHAIN_TOKEN=... lab/identity/walk.sh
```

The walk (`frontend/e2e/identity/01-gateway.spec.ts`, phases selected by tag):

1. Identity up, the fixtures created (the client secret is generated by the walk, kept in a private file and handed to the
   fixture and to the gateway; the lab's administrator password is read from its container; nothing secret is printed).
2. OpenBinding's lab (project `obf5id`, http://localhost:18198) on an empty database.
3. `@bootstrap`: `admin` signs in first and becomes administrator by `BOOTSTRAP_ADMIN_SUB`.
4. `seed_lab`; then the seeded `lab-orgadmin` is marked verified (the `clash` fixture uses its address).
5. The main phase: `member`'s first sign-in (a taken username, then its own; its email verified by the code sign-in),
   its return without a code, five parallel renewals after 35 s, logout (the captured token refused, Identity asking for
   an email again); `research` on RESEARCH; `clash` refused (`account_not_linked`); `squat` provisioned with the address an
   unverified seeded account held; `norole` refused (`access_denied`); the account page answering.
6. `@signup` (the registration screen answers; a native registration by email code from the sign-in page, refused until the permission is granted), Keycloak's view
   of its verified email, the grant, `@granted`.
7. Post-checks in PostgreSQL: one refresh for the five renewals, the identities, the released email, the audit rows.
8. `@rollback`: the gateway recreated with `AUTH_PROVIDER=local`; the old session refused, a password reset and a local
   sign-in reach the same account.
9. Always: fixtures deleted, both stacks down with their volumes, logs and results in `WALK_LOGS`.

Every address is `@example.invalid` or `@research.example`, except the `clash` and `squat` fixtures, which use the
synthetic `@example.org` addresses of two seeded lab users. Only the Identity lab's Mailpit sees them.

**Memory.** Identity (about 3 GiB, Keycloak capped at 2 GiB) and the OB lab (`lab/tests/test_lab_compose.py`
`EXPECTED_MIB`) fit together only with no other lab stack up; `up.sh` checks. On a shared docker host, run the walk when
no other lab runs.

**Cookies on localhost ignore ports**: the OB lab's cookies reach Identity at `localhost:18000`, which ignores them;
Keycloak's are scoped to its realm path. Production hosts differ, so this is a lab artefact only.
